# 阶段五报告：傲娇重构

规格来源：m03635《拟人聊天插件重构工程提示词（最终版）》阶段五。
代码版本：v1.6.0。测试：`tests/test_tsundere.py`（10 组）。

## 1. 诊断：不是傲娇太强，而是傲娇被降级成了标签

旧实现把 `assets/persona.json` 里 `tsundere.negation_patterns[].pattern` 原样拼进人格块，
并在前面写「嘴硬时可以这样写」。这些 pattern 本身就是**关于傲娇的元描述**
（「我才没有…」+ 后半句找补），模型于是学会的是「先声明否认，再解释我没在否认」——
替观众完成了本应由观众完成的解读。表现就是「才不是特意 XX」这种一眼假的句子。

- 关心被否定的形式吃掉：句子里只有态度，没有具体行动或信息可追溯。
- 否定是应激式的：只有在被戳穿时才否定，而不是稳定语气底色。
- 傲娇与温柔互相取消：要么全刺，要么突然告白。

## 2. 三条替代路径（行为，而不是句式）

| 路径 | 做法 | 反例 |
| --- | --- | --- |
| ① 行动先行 + 借口收尾 | 先做具体的事/给具体信息，再用不暴露柔软的借口解释动机 | 「才不是特意给你带的」 |
| ② 毒舌包裹真实信息 | 用吐槽/嫌弃的语气说出真实内容，信息是真的 | 「哦，你还知道回来」 |
| ③ 关心以「泄露」出现 | 让对方看见你在意，但立刻收回或把话题带走 | 「我有点担心你」（太直白） |

人格块现在只输出这三条 + 铁律，不再输出 `negation_patterns` 的句式文本。

## 3. 硬约束：元话语式否定零容忍

- 短语表 `TSUNDERE_FORBIDDEN`：才不是特意 / 才不是为了 / 才不是关心 / 才没有想 / 我才没有 /
  我才不关心 / 我才不在乎 / 我才不是 / 又不是为了你 / 并不是为了 / 别误会。
- 正则表 `TSUNDERE_META_RE` 覆盖变体：`才不是.{0,8}(特意|故意|专门|为了|担心|在乎|关心|想)`、
  `我才(没有|不是).{0,8}(…)`、`又不是为了你`、`别误会`。
- 命中即丢弃该条并重生成（`tsundere_max_retry` 默认 1 次），全部失败则本次不发。
- 原 L11 断言里的四条仍然成立，另加变体与不误杀（「顺手带的，吃不吃？」要放行）。

## 4. 审校代理（三条停止条件）

`_living_tsundere_review(text, umo, affect_text)`：让模型只做判定，输出 JSON
`{"pass": bool, "reason": str, "rewrite": str}`。

1. 零元话语：出现动机否认/替对方解读即 FAIL。
2. 可追溯的关心：若含关心，必须能指认承载在哪个具体行动、信息或事由上。
3. 语气一致：毒舌是底色；情绪越负面越「加密」，不能变直白告白或冷淡敷衍。

处理：PASS → 原文；FAIL 且有改写 → 改写（仍需过静态硬约束）；否则丢弃。
审校调用异常或 JSON 解析失败 → **放行原文**（不因审校故障阻断发送），只记日志。

## 5. 情感耦合：负面越强，傲娇越「加密」

`_tsundere_encrypt_level(umo)` 读 AffectCore 的 PAD 与沉默严重度：

| 档 | 条件 | 提示词倾向 |
| --- | --- | --- |
| 0 | p > 0.1 且无沉默负面 | 嘴上嫌弃归嫌弃，该给的信息直接给 |
| 1 | p ≤ 0.1 或有沉默迹象 | 嘴更硬、关心更藏，用嫌弃或别的话题带过 |
| 2 | p ≤ −0.25 或沉默严重度 ≥ 0.5 | 不许直说难过、不许问「你是不是不想理我」；用抱怨/挑刺/装作随口一问确认对方还在 |

即：不把「我有点难过你一直没理我」说出口，而说抱怨式确认对方是否还在的话。

## 6. 覆盖正常对话

此前傲娇只约束主动消息。v1.6.0 增加 `@filter.on_llm_request(priority=99996)`：
把三路径 + 铁律以紧凑块（`tsundere_chat_block`）追加进 `req.system_prompt`，
幂等标记「【傲娇怎么写」防止重复注入；`tsundere_chat_inject` 可关闭。

## 7. 与规格的偏离（显式声明）

1. 判定用 LLM 审校而不是规则解析——「可追溯的关心」「语气一致」无法用规则判，规则只做第一层硬过滤。
2. 加密分三档而不是连续函数——规格要求「可辨识上升」，三档在提示词里更容易稳定生效。
3. 正常对话采用 system prompt 注入而不是替换整份人格——插件不改写服务器人格文档，只叠加傲娇层。

## 9. 遗留

- 正常对话的人格主体仍来自 AstrBot 服务器侧人格配置；本阶段只叠加傲娇层，不做人格整份接管。
- 「可追溯的关心」依赖审校模型质量，尚未做人工抽检集（阶段六整合彻查时补）。
