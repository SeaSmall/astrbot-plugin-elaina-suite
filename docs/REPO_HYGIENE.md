# 仓库脱敏约定（REPO_HYGIENE）

本仓库是 **public** 仓库。历史里曾出现个人与基础设施标识（QQ 号、平台 openid、服务器域名/端口、
用户名、内网 IP、容器名、少量对话原句）。2026-10-29 已用 `git-filter-repo` **重写全部历史**强推清理，
并且把残留的占位型长标识也一并删掉了 —— 现在文档和测试里**不保留任何具体账号、主机、IP、路径**。

## 规矩：不写真实值，也不留无意义的长占位

| 需要表达的东西 | 怎么写 |
| --- | --- |
| 主人 QQ 号 / 其他 QQ 号 | 文档写 `<qq>`；测试用明显合成的短值，如 `10001` |
| 平台 openid（微信 / QQ 官方） | 文档写 `<openid>`；测试用 `openid_test` |
| 群 openid | 文档写 `<group_openid>` |
| 服务器地址 / 用户名 / 端口 | **直接删掉**，需要提就写「服务器（已脱敏）」；不要编假域名/假主机名 |
| 内网 IP | 写「内网主机」，不要写具体网段 |
| 容器 / 服务名 | 写 `astrbot`（AstrBot 的通用叫法，不含业务含义即可） |
| 共享作用域 id | 文档写 `<scope>`；测试/示例用 `testuser` |
| 聊天记录样例 | 写「对话原句已脱敏」，不要贴原句 |
| 工作区里的私人文件名 | 泛化成 `timetable.md`、`project_README.md` 这类中性名 |

核心原则：**能删就删，不能删就用 `<qq>` / `<openid>` 这种尖括号占位，不要造新的假域名/假账号。**
假值看着无害，但会让人误以为仓库里记录过真实拓扑。

## 提交前自检

```bash
# 1) 真实值残留（把尖括号里的内容换成你本地笔记里的真实值，别把真实值写进仓库）
git grep -nE '<QQ号>|<openid>|<域名>|<用户名>|<内网IP>|<容器名>' -- . ':!meme'

# 2) 结构类风险：邮箱 / 手机号 / key 形态
git grep -nE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|\b1[3-9][0-9]{9}\b|tp-[A-Za-z0-9]{16,}|sk-[A-Za-z0-9]{20,}|eyJ[A-Za-z0-9_-]{20,}|BEGIN [A-Z ]*PRIVATE KEY' -- . ':!meme'

# 3) 不该入库的缓存
git ls-files | grep -E '__pycache__|\.pyc$' || echo "ok: 无缓存文件"
```

期望：第 1、2 条无输出，第 3 条打印 `ok`。

## 其它说明

- `.gitignore` 已忽略 `__pycache__/`、`*.py[cod]`、`.venv/`、`*.log`、IDE 目录。
- 真实服务器配置（含 API Key、真实平台标识）只在服务器 `/opt/astrbot/data/config/` 下，**不进仓库**；
  仓库里的 `_conf_schema.json` 只描述键与默认值。
- `assets/persona_source/` 是插件自带人格的素材存档，属有意公开内容；其中的清单文件已去掉服务器信息字段。
- 若真实值又被提交进来：不要只改工作树——需要再次 `git-filter-repo --replace-text` 重写历史并强推，
  同时通知所有协作者重新 clone。
